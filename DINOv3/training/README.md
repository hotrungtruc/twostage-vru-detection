# DINOv3 Cyclist State Classification - Training Module

Welcome to the Training Module for the **DINOv3 Cyclist State Classification** project. This module encompasses the end-to-end pipeline for training a lightweight classifier head on top of a frozen DINOv3 feature extractor to classify the behavioral state of a cyclist (e.g., `riding` vs. `pushing`).

---

## Directory Structure

The repository is currently organized into two primary training iterations:

```text
training/
├── v1_old/                  # Initial Version (Baseline)
│   ├── labeled_data_v1_old/ # Combined dataset directory (classes merged)
│   ├── output/              # Target directory for checkpoints, CSV logs, and plots
│   └── train_v1_old.py      # Training script (Auto-generates random 80-20 splits)
│
├── v2_new/                  # Advanced Version (Optimized Pipeline)
│   ├── labeled_data_v2_new/ # Pre-split dataset directory (structured into train/ and valid/)
│   ├── output/              # Target directory for checkpoints, CSV logs, and plots
│   └── train_v2_new.py      # Improved training script with pre-split data support, dHash-based duplicate reduction, class weighting, and threshold tuning.
│
└── test_dHash/              # Standalone utility for testing Image Deduplication logic
```

### Datasets Overview

> [!NOTE]
> The dataset is continuously updated. The following sample counts reflect the current version of the data and are subject to change over time.

- **`v1_old` Dataset**: Composed of raw frame crops extracted directly from the local surveillance video `00045`, augmented with 49 internet-sourced images for the 'pushing' class.
  - Total Samples: 2,071
- **`v2_new` Dataset**: Sourced from the **HICO-DET** (Humans Interacting with Common Objects - Detection) dataset and augmented with custom crops extracted from the local surveillance video `00044` to dramatically improve real-world generalization and prevent overfitting on specific camera angles.
  - Training Set: 1,854 samples (1,370 Riding, 484 Pushing)
  - Validation Set: 876 samples (801 Riding, 75 Pushing)
  - Total Samples: 2,730

**Class Mapping:**
Class mapping is generated by `torchvision.datasets.ImageFolder`. For the current `v2_new` dataset, the class order stored in the checkpoint is:
- `class 0 = pushing`
- `class 1 = riding`

The inference pipeline must load `class_names` from the checkpoint instead of hard-coding class labels.

### Key Advancements in `v2_new`
- **Dynamic In-memory Deduplication**: Seamlessly integrates Difference Hashing (dHash) within the DataLoader. dHash is used to reduce near-duplicate samples within each split and mitigate overfitting from sequential video frames.
- **Optimal Threshold Tuning**: After training, validation predictions are used to compute a precision-recall curve for the pushing class. The threshold that maximizes the F1-score is stored in the `.pth` checkpoint metadata.
- **Auto Path Mapping**: Refactored to utilize relative paths dynamically. The codebase can be cloned into any directory across any operating system (Windows/Linux/macOS) and executed immediately without hardcoded path dependencies.
- **Smart Data Splitting**: Natively processes pre-split directory structures (`train/` and `valid/`) and features a robust telemetry system that reports exact subset ratios prior to the initiation of the training loop.

## Environment Setup

The repository supports both containerized deployment via Docker (Recommended) and native local installation.

### Method 1: Docker Deployment (Recommended)
Ensure Docker Desktop is installed. Navigate to the root directory of the project and execute the provided scripts. You can explicitly select the training pipeline version (`v1` or `v2`). If omitted, it defaults to the latest `v2` pipeline.

- **Windows Users**: 
  ```bash
  run_train_docker.bat v2  # (or run_train_docker.bat v1)
  ```
- **Mac/Linux Users**: 
  ```bash
  ./run_train_docker.sh v2 # (or ./run_train_docker.sh v1)
  ```

*Note: The Docker scripts build the environment and run the selected training pipeline. For NVIDIA GPU acceleration on Linux, the Docker command must be modified to include `--gpus all` and the NVIDIA Container Toolkit must be installed.*

### Method 2: Native Local Installation
1. Install core dependencies (using `opencv-python-headless` for headless/server environments):
```bash
pip install "timm>=1.0.20" tqdm matplotlib "numpy<2.0.0" opencv-python-headless scikit-learn seaborn pillow
```

2. Install PyTorch (Choose based on your OS):

**For Windows/Linux (with NVIDIA GPU for CUDA 12.1):**
```bash
pip uninstall torch torchvision torchaudio -y
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
```

**For macOS (Apple Silicon):**
For macOS Apple Silicon, install the standard PyTorch package and let the script use MPS if supported.
```bash
pip install torch torchvision torchaudio
```

## Execution Guide

The codebase provides a robust Command Line Interface (CLI). To initiate the training sequence using the optimized `v2_new` pipeline, run:

```bash
cd training/v2_new
python train_v2_new.py
```

### Advanced Configuration
You can explicitly define hyperparameters by appending arguments to the execution command:

```bash
python train_v2_new.py \
    --epochs 15 \
    --batch-size 64 \
    --lr 0.0005 \
    --threshold 8
```

> [!NOTE]
> The training script automatically selects CUDA, MPS, or CPU depending on the available hardware.

**Critical Parameters:**
- `--threshold`: Defines the Hamming Distance tolerance for the dHash deduplication logic (Default: `8`). 
  - `5`: Strict tolerance (Filters exact or near-exact duplicates).
  - `8-10`: Optimal range for filtering sequential frames extracted from security cameras or dashcams.
- `--workers`: Configures the number of parallel data-loading subprocesses (Default: `4`). Highly recommended to increase this value to `8` or `16` on Linux/Windows systems with a high core count. *(Note: macOS limitations are handled automatically by the script)*.

## Output Artifacts
Upon completion of the training lifecycle, all artifacts are persisted sequentially into the `output/` directory:
1. `dinov3_lightweight_classifier_v2_new.pth`: Checkpoint file containing the classifier `model_state_dict`, `class_names`, `backbone_name`, and `optimal_threshold`.
2. `training_stats_v2_new.csv`: Epoch-wise telemetry detailing Loss and Accuracy metrics.
3. `training_report_v2_new.png`: A plotted visualization analyzing the Training and Validation performance curves.
4. `classification_report_v2_new.txt`: Final precision, recall, and F1-score evaluation metrics.
5. `confusion_matrix_v2_new.png`: Visual confusion matrix heatmap.

## Deploying Checkpoint to Inference

By default, the inference pipeline expects the model weights to be located at `models/weights/dinov3_lightweight_classifier.pth` in the project root.

To deploy your newly trained checkpoint for inference, navigate to the project root and execute the following commands to copy and rename the `.pth` file:
```bash
mkdir -p models/weights
cp training/v2_new/output/dinov3_lightweight_classifier_v2_new.pth \
   models/weights/dinov3_lightweight_classifier.pth
```
